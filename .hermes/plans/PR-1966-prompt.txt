THE TASK

Put the relay toggle's shape where the radio group is, with "Direct" on one side and "Smart" on the
other, keep the form control and the values that are saved unchanged, and keep the default on Smart.

HARD RULES

- The layout mirrors the relay: left column with a text, the centred toggle button with the
  toggle-switch image, right column with a text. Row/col classes as in the reference, so it lines up
  with the rest of the dialog.
- The toggle must point at the SELECTED side: the side whose state is active carries the image that
  points to it, and the two texts sit on the sides the image points between. Be explicit in your
  report about which text you put where and why.
- Keep the stored value semantics exactly: the form control still carries the channel values the rest
  of the component uses (the ChatChannel constants), not the display texts. Clicking the toggle
  flips between them; saving and reopening an existing personality shows the stored state.
- The condition stays: the Smart option only exists when showSmartChannelControl is true. When it is
  false there must still be a valid Direct value and no control offering a switch that cannot switch.
  Say in your report how you handled that case.
- This is both the Add and the Edit dialog - one template serves both. Do not break the edit path,
  where the control must show the personality's stored channel, not the default.
- Test ids follow the relay's TGL_ prefix convention rather than the old RBN_ radio prefix. The specs
  that query RBN_Channel_Smart / RBN_Channel_Direct are adapted in the same change - do not keep the
  radio elements only to satisfy an old id.
- No [disabled] state: unlike the relay, both positions are always selectable. Do not invent an
  unavailable case.
- Do not touch src/app/program/pib-blockly/**. That tree is generated from pib-backend and
  guard-blockly-single-source.yml rejects a pull request that edits it.
- Tests: npx ng test --watch=false --browsers=NoSandbox with CHROME_BIN pointing at a Chromium.
  Cerebra does not use Jest; a Jest run produces meaningless failures.
